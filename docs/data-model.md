# Minimum MongoDB Data Model

Status: Proposed contract for implementation.

This document defines the target data model for the committed MLP.
It does not claim that these collections, validations, or permissions are
already implemented.

MongoDB remains as the database engine for this release.

## 1. Scope

The minimum collections are:

- users
- companies
- products
- offers
- vacancies

Excluded from this release:

- Company branches.
- Geolocation, coordinates, maps, proximity search, and geographic filters.
- Consumer accounts.
- Favorites and promotion alerts.
- Internal CVs, applicant profiles, and job applications.
- Payments, carts, orders, shipping, and checkout.
- Automated institutional validation or official accreditation.

Textual addresses and vacancy locations are allowed.

## 2. Shared conventions

### Identifiers and references

MongoDB stores `_id` as an ObjectId.

The API exposes it as a string named `id`:

```json
{
  "id": "507f1f77bcf86cd799439011"
}
```

MongoDB `_id` is not exposed as a second public identifier.

References are stored as ObjectIds and serialized as strings:

- ownerUserId
- companyId
- productId

New identifiers are generated by the backend. Clients do not choose IDs.

### Shared timestamps

Every collection includes:

| Field | Stored type | Rule |
| --- | --- | --- |
| `_id` | ObjectId | Generated by MongoDB/backend. |
| `createdAt` | Date | Set by the backend at creation; immutable. |
| `updatedAt` | Date | Set by the backend when the record changes. |

The API serializes dates as ISO 8601 timestamps with a timezone.

Examples use UTC:

```text
2026-10-16T18:00:00.000Z
```

### Money

Prices use integer minor units:

```json
{
  "priceCents": 129900,
  "currency": "MXN"
}
```

This represents MXN 1,299.00.

- priceCents must be a non-negative safe integer.
- MXN is the supported currency for the MLP.
- Currency defaults to MXN when omitted on creation.
- Monetary strings and floating-point prices are not stored in priceCents.
- The portal does not certify prices or discounts institutionally.

### Optional fields

Optional text and URL fields may be absent.

On update, null explicitly removes an optional field.
Required fields cannot be removed or set to null.

### External URLs

URL fields must contain absolute HTTP or HTTPS URLs with a hostname.

Reject unsupported schemes, embedded credentials, and malformed URLs.
HTTPS is preferred.

The backend validates URL syntax but does not fetch the destination.
Syntax validation does not certify the destination or its operator.

## 3. users

Purpose: authenticate business representatives and administrators.

| Field | Type | Required/default | Rules |
| --- | --- | --- | --- |
| email | string | Required | Trimmed, lowercase, valid email syntax, maximum 254 characters. |
| passwordHash | string | Required | Argon2id hash generated by the backend. Never returned by the API. |
| firstName | string | Required | Trimmed; 1–100 characters. |
| lastName | string | Required | Trimmed; 1–100 characters. |
| phone | string | Optional | Trimmed; maximum 30 characters. |
| role | string enum | Default: business | Allowed values: business, admin. Assigned through trusted server logic. |
| isActive | boolean | Default: true | Inactive users cannot authenticate or access protected operations. |
| tokenVersion | integer | Default: 0 | Internal counter used to invalidate previously issued JWTs. Never returned. |

The registration request contains a plaintext password, not passwordHash.

Password policy:

- 12–128 characters.
- Passwords are not trimmed or silently modified.
- Passwords and hashes are never logged.
- Password confirmation is a frontend validation field and is not persisted.

Public registration always creates a business account.

Clients cannot assign role, isActive, tokenVersion, or passwordHash.
Administrators are provisioned through a controlled local setup procedure
implemented and documented under US-04.1.

No consumer role or public user directory is provided.

### User responses

The authenticated user may read their own account through /users/me.
Administrators may read sanitized user records.

Sanitized records contain:

- id
- email
- firstName
- lastName
- phone, when present
- role
- isActive
- createdAt
- updatedAt

Passwords, hashes, and tokenVersion are always excluded.

## 4. companies

Purpose: store a company profile and its authorized representative.

| Field | Type | Required/default | Rules |
| --- | --- | --- | --- |
| ownerUserId | ObjectId reference | Required | References an existing business user. |
| name | string | Required | Trimmed; 1–200 characters. |
| rfc | string | Required | Trimmed, uppercase; basic 12/13-character RFC syntax validation only. |
| category | string enum | Required | Uses the company category values below. |
| physicalStore | boolean | Required | Indicates whether the company has a physical store. |
| description | string | Optional | Maximum 5,000 characters. |
| address | string | Conditional | Required when physicalStore is true; maximum 500 characters. |
| contactEmail | string | Optional | Public business contact; valid email syntax. |
| contactPhone | string | Optional | Public business contact; maximum 30 characters. |
| websiteUrl | string | Optional | Valid external URL. |
| isActive | boolean | Default: false | Representative-controlled publication state. |
| isHidden | boolean | Default: false | Administrator-controlled internal moderation state. |

Initial category values match the existing directory frontend:

- Alimentos
- Moda
- Electrónica
- Hogar
- Servicios
- Salud

The RFC syntax policy checks format only.
It does not contact SAT or imply registration, accreditation, or approval.

ownerUserId is assigned from the authenticated business user on creation.

An administrator creating a company must explicitly provide a valid
ownerUserId belonging to an existing business account.

Ownership transfers are outside the minimum API.

One representative may own multiple companies.
This does not introduce company branches.

### Company responses

Public fields:

- id
- name
- category
- physicalStore
- description, when present
- address, when present
- contactEmail, when present
- contactPhone, when present
- websiteUrl, when present
- createdAt
- updatedAt

Private management responses additionally include:

- ownerUserId
- rfc
- isActive
- isHidden

Public contact fields are intentionally published business contacts.
The representative's account email and phone are not copied into them
automatically.

## 5. products

Purpose: store products managed by a company.

| Field | Type | Required/default | Rules |
| --- | --- | --- | --- |
| companyId | ObjectId reference | Required | References an existing company the caller may manage. Immutable. |
| name | string | Required | Trimmed; 1–200 characters. |
| description | string | Required | Trimmed; 1–5,000 characters. |
| category | string enum | Required | Uses the category values listed for companies. |
| priceCents | integer | Required | Non-negative safe integer. |
| currency | string enum | Default: MXN | MXN only for the MLP. |
| imageUrl | string | Optional | Valid external URL. |
| isActive | boolean | Default: false | Representative-controlled publication state. |
| isHidden | boolean | Default: false | Administrator-controlled internal moderation state. |

The product category does not have to equal its company's category.

Public product responses include:

- id
- companyId
- name
- description
- category
- priceCents
- currency
- imageUrl, when present
- createdAt
- updatedAt

Private management responses additionally include isActive and isHidden.

## 6. offers

Purpose: publish a product offer with price, terms, and validity dates.

| Field | Type | Required/default | Rules |
| --- | --- | --- | --- |
| companyId | ObjectId reference | Required | References an authorized company. Immutable. |
| productId | ObjectId reference | Required | References a product belonging to companyId. Immutable. |
| title | string | Required | Trimmed; 1–200 characters. |
| description | string | Required | Trimmed; 1–5,000 characters. |
| priceCents | integer | Required | Non-negative safe integer. |
| currency | string enum | Default: MXN | MXN only for the MLP. |
| startsAt | Date | Required | Valid timestamp with timezone. |
| endsAt | Date | Required | Must be later than startsAt. |
| terms | string | Required | Trimmed; 1–5,000 characters. |
| sellerUrl | string | Required | Valid external URL. |
| isActive | boolean | Default: false | Representative-controlled publication state. |
| isHidden | boolean | Default: false | Administrator-controlled internal moderation state. |

An offer cannot reference another company's product.

Offer prices are stored independently from the product's current price.
Changing the product price does not silently rewrite existing offers.

There is no institutional price-validation or certification workflow.

Public offer responses include:

- id
- companyId
- productId
- title
- description
- priceCents
- currency
- startsAt
- endsAt
- terms
- sellerUrl
- createdAt
- updatedAt

Private management responses additionally include isActive and isHidden.

The frontend may obtain the company and product through their public detail
endpoints. Expanded or embedded records are not required by this contract.

## 7. vacancies

Purpose: publish a job opening with an external application channel.

| Field | Type | Required/default | Rules |
| --- | --- | --- | --- |
| companyId | ObjectId reference | Required | References an authorized company. Immutable. |
| position | string | Required | Trimmed; 1–200 characters. |
| type | string enum | Required | temporary or permanent. |
| description | string | Required | Trimmed; 1–5,000 characters. |
| location | string | Required | Textual location; 1–500 characters. |
| applicationUrl | string | Required | Valid external URL. |
| isActive | boolean | Default: false | Authorized company can publish or hide the opening. |

location is descriptive text, not a geographic search field.

Public vacancy responses include:

- id
- companyId
- position
- type
- description
- location
- applicationUrl
- createdAt
- updatedAt

Private management responses additionally include isActive.

No CV, candidate profile, or application record is stored.

## 8. Ownership and authorization

For management operations performed by a business user:

- Company access requires company.ownerUserId to match the authenticated user.
- Product access requires ownership of product.companyId.
- Offer access requires ownership of offer.companyId.
- Vacancy access requires ownership of vacancy.companyId.
- Referenced products must belong to the referenced company.

The backend resolves these relationships.
A companyId supplied by the client is not proof of authorization.

Administrators may access management resources across companies.

Business users cannot set or change isHidden.
Clients cannot change ownership through an ordinary update.

Frontend visibility is not an authorization control.

## 9. Public visibility

A company is public when:

```text
company.isActive == true
AND company.isHidden == false
```

A product is public when:

```text
product.isActive == true
AND product.isHidden == false
AND its company is public
```

An offer is public when:

```text
offer.isActive == true
AND offer.isHidden == false
AND its company is public
AND its product is public
AND offer.startsAt <= serverNow
AND serverNow < offer.endsAt
```

A vacancy is public when:

```text
vacancy.isActive == true
AND its company is public
```

The same rules apply to public lists, getMany requests, and detail routes.

These predicates are evaluated by the backend on each query.
A scheduled job is not required merely to exclude expired offers.

Hiding a company does not rewrite its child records.
Its products, offers, and vacancies become publicly unavailable through
the parent visibility rule.

Reactivating a company does not override any child's own state or dates.

Internal visibility/moderation never means governmental accreditation.

## 10. Deactivation and referential integrity

DELETE on companies, products, offers, and vacancies performs a soft
deactivation by setting isActive to false.

It does not physically delete the MongoDB document.

This preserves references and prevents orphaned records.

Management queries may still return inactive or hidden records to authorized
users. Public queries exclude them.

An authorized owner may reactivate a record, but cannot override isHidden.

References and publication requirements must be revalidated on writes.
Public queries must also enforce parent visibility.

## 11. Required indexes

| Collection | Index | Purpose |
| --- | --- | --- |
| users | email, unique | Prevent duplicate normalized login identities. |
| companies | rfc, unique | Prevent duplicate normalized company RFCs. |
| companies | ownerUserId | Resolve ownership and management lists. |
| companies | category, physicalStore | Support directory filters. |
| products | companyId | Support company-scoped access. |
| products | category | Support catalog filtering. |
| offers | companyId | Support company-scoped access. |
| offers | productId | Resolve product relationships. |
| offers | isActive, isHidden, startsAt, endsAt | Support visibility/date queries. |
| vacancies | companyId | Support company-scoped access. |
| vacancies | type, isActive | Support public vacancy filters. |

MongoDB's default unique _id index remains in place.

Indexes do not replace authorization or field validation.
Text-search optimization may be evaluated later; it is not required to
define this minimum contract.

## 12. Legacy transition

The inspected starter (17.10.2026) currently uses:

- usuarios.
- productos.
- Numeric custom product IDs.
- A username-like value as the login response ID.

The target uses:

- users, companies, products, offers, vacancies.
- ObjectIds internally.
- String IDs in API responses.
- The actual user identifier in authentication responses.

Legacy numeric identifiers must not be converted blindly into ObjectIds.

No data migration, deletion, or collection rename is performed by issue TECH-02.

US-04.1 and US-06.1 must explicitly decide whether any local demonstration data is migrated or replaced with agreed fixtures.
